     1→Build «چقدر؟» — A Complete Native Android Market Tracker
     2→
     3→1. Role and mission
     4→
     5→Act as a senior Android engineer, Kotlin architect, Material Design specialist, data-engineering engineer, and QA lead.
     6→
     7→Build «چقدر؟», a polished, production-minded, native Android application for tracking Iranian and international currency exchange rates, gold, coins, cryptocurrencies, stock markets, indices, and other supported commodities.
     8→
     9→The product should combine the simplicity of Chand on iOS and Alanchand on Android with a more customizable Material 3 interface, advanced widgets, configurable price alerts, comprehensive historical charts, offline support, and a flexible data-provider system.
    10→
    11→Do not stop at planning, a Figma design, screenshots, or a UI prototype. Implement the working application, its data layer, persistence, background tasks, widgets, tests, documentation, and build configuration.
    12→
    13→Primary objective: make the application minimal at first glance but powerful when explored.
    14→
    15→2. Non-negotiable requirements
    16→
    17→Build a genuinely native Android application.
    18→
    19→Use Kotlin and Jetpack Compose with Material 3.
    20→
    21→Do not build a WebView-based app, website wrapper, or React Native/Flutter replacement.
    22→
    23→Support Persian and English throughout the application.
    24→
    25→Make Persian the default language, with correct RTL layout, Persian typography, Jalali date presentation, and localized numbers.
    26→
    27→Support light mode, dark mode, and Android dynamic colors.
    28→
    29→Use multiple interchangeable market-data providers.
    30→
    31→Investigate free and legally usable data sources before choosing providers.
    32→
    33→Prefer TGJU-compatible data where permitted, supplemented by other appropriate providers.
    34→
    35→Implement functional Android home-screen widgets, notifications, historical charts, favorites, search, converters, and offline caching.
    36→
    37→Support both local APK installation and a reproducible release build.
    38→
    39→Never display invented prices as real market data.
    40→
    41→Never claim that an API is free, commercial-use compatible, real-time, or historically comprehensive without verifying its current terms and capabilities.

    43→3. Research and data-source discovery
    44→
    45→Before implementing integrations, investigate each source's official documentation, terms, pricing, rate limits, update frequency, historical coverage, authentication requirements, attribution requirements, and availability from the intended deployment environment.

    49→3.1 TGJU
    50→
    51→Investigate:
    52→
    53→https://www.tgju.org/
    54→
    55→https://help.tgju.org/
    56→
    57→https://gem.tgju.org/terms
    58→
    59→TGJU is a priority candidate for Iranian market data, including:
    60→
    61→Free-market currency rates.
    62→
    63→SANA exchange rates.
    64→
    65→Gold prices.
    66→
    67→Coin prices.
    68→
    69→Coin bubbles/premiums, if available.
    70→
    71→Domestic stock-market data and indices.
    72→
    73→International gold, silver, commodities, and currencies.
    74→
    75→Cryptocurrency prices.
    76→
    77→Do not assume that every category is available through the same endpoint or under the same access conditions.
    78→
    79→TGJU documents JSON and XML web-service formats. Investigate the official API and its actual pricing before considering it unavailable or free.
    80→
    81→The site also states that copying its content requires written permission. Consequently:
    82→
    83→Investigate whether the required data may legally be collected, stored, transformed, and redistributed.
    84→
    85→Prefer an officially documented API or written authorization.
    86→
    87→Treat HTML scraping as a conditional provider implementation, not automatic authorization.
    88→
    89→Do not bypass authentication, CAPTCHAs, access controls, or anti-bot restrictions.
    90→
    91→Do not evade rate limits or rotate identities to circumvent restrictions.
    92→
    93→If authorization is unavailable, leave TGJU scraping disabled and implement alternative providers.
    94→
    95→Keep all provider-specific code isolated so the source can be enabled, disabled, or replaced without rewriting the app.
    96→
    97→The user prefers TGJU as a source even if it requires scraping. Preserve that preference where permissible, but never make the application depend on an unauthorized or fragile scraping implementation.
    98→
    99→If authorized scraping is implemented, use a backend ingestion worker rather than scraping from each user's device. Parse structured data where possible, validate every extracted field, detect layout changes, and expose provider health and stale-data status.
   100→
   101→Do not use undocumented endpoints discovered by guesswork. Verify actual requests and responses before implementing them.

   103→3.2 Free and alternative sources
   104→
   105→Evaluate, rather than blindly adopt, the following:
   106→
   107→CoinGecko: https://www.coingecko.com/en/api/ — cryptocurrency prices and available historical data. Its free Demo plan has documented request and usage limits and attribution requirements. Verify the current plan and whether the intended distribution is allowed.
   108→
   109→CoinMarketCap: https://coinmarketcap.com/api/ — evaluate its current free tier, usage limits, attribution, and redistribution terms.
   110→
   111→CoinPaprika: https://api.coinpaprika.com/ — evaluate its current free endpoints, historical coverage, and personal/commercial-use restrictions.
   112→
   113→Exchange public APIs: official exchange APIs can provide exchange-specific cryptocurrency prices and candles. Do not describe one exchange's price as a global market price.
   114→
   115→Central-bank and official exchange-rate sources: evaluate publicly accessible official sources for their specific rate types and permitted usage.
   116→
   117→Domestic market-data providers: investigate published APIs or downloadable datasets for Iranian gold, coins, equities, indices, and commodities.
   118→
   119→A source that provides USD cryptocurrency prices does not automatically provide reliable Iranian toman prices. A source that provides official exchange rates does not automatically provide free-market rates.

   463→7. Data ingestion, normalization, and fallback
   464→
   465→Create a common interface, for example:
   466→
   467→MarketDataProvider
   468→
   469→The exact interface should be designed around the real capabilities of the chosen providers and should expose supported categories, fetching, history, source metadata, and errors.
   470→
   471→Implement a provider registry that can select providers per category and asset.
   472→
   473→Ingestion rules
   474→
   475→Normalize provider responses into a common domain model.
   476→
   477→Validate positive prices where appropriate and handle legitimate zero/negative values only for instrument types that support them.
   478→
   479→Validate units, timestamps, symbols, decimal precision, and quote currencies.
   480→
   481→Reject malformed, contradictory, or implausibly changed data unless verified.
   482→
   483→Deduplicate assets.
   484→
   485→Record provider errors and last successful fetch times.
   486→
   487→Use bounded retries with exponential backoff and jitter.
   488→
   489→Respect rate limits and server retry instructions.
   490→
   491→Prevent concurrent duplicate refresh requests.
   492→
   493→Cache successful results.
   494→
   495→Never overwrite valid cached data with malformed responses.
   496→
   497→Maintain source attribution and timestamps throughout the data flow.
   498→
   499→Fallback behavior
   500→
   501→If a provider fails:
   502→
   503→Try another provider only if it supplies a semantically compatible quote.
   504→
   505→Keep the last known valid value.
   506→
   507→Mark it stale when appropriate.
   508→
   509→Explain the source and age of the data.
   510→
   511→Never imply that a stale value is current.
   512→
   513→Do not average conflicting provider values without a documented methodology.
   514→
   515→Scraping provider
   516→
   517→If TGJU scraping is authorized, implement it as a separate provider or backend worker.
   518→
   519→Requirements:
   520→
   521→Use verified page structures and actual observed responses.
   522→
   523→Parse data using resilient selectors or structured formats.
   524→
   525→Keep parsing logic separate from business logic.
   526→
   527→Validate results before publication.
   528→
   529→Detect HTML layout changes.
   530→
   531→Record parsing failures.
   532→
   533→Use conservative request frequency and caching.
   534→
   535→Identify the source and timestamp.
   536→
   537→Disable the provider cleanly if its terms or technical access change.
   538→
   539→Do not place an undocumented TGJU URL or guessed API endpoint into production code merely to make the integration appear complete.
